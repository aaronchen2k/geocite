# 诊断执行第五步日志入口设计

## 目标

在诊断执行页面中，为第五步“AI 问答采样”的右上角状态区域提供日志入口，便于确认该入口的视觉位置。

## 交互与范围

- 临时地，仅第五步且状态为 `pending` 或 `running` 时显示日志图标；视觉确认后恢复为仅 `running`。
- 图标位于右上角状态行中旋转的执行状态图标左侧。
- 图标为可访问的按钮，具备中文无障碍标签与悬停提示。
- 点击只执行 `console.log('日志被点击')`，不打开面板、不请求接口，也不改变执行状态。
- 第五步处于其他状态，以及其余六个步骤时，行为和视觉均保持不变。

## 实现边界

改动局限于诊断执行前端组件。复用现有 Iconify 图标和按钮样式，不增加接口、状态存储、国际化文案或后端改动。

## 验收

1. 第五步为 `pending` 或 `running` 时，右侧状态显示日志按钮；为 `running` 时仍保留原有旋转图标，日志按钮在左。
2. 点击日志按钮会在浏览器控制台输出精确文本 `日志被点击`。
3. 第五步为 `pending`、`running` 之外的状态时没有日志按钮；视觉确认后移除 `pending` 的临时显示条件。
4. 其他步骤运行时没有日志按钮，原行为不受影响。
