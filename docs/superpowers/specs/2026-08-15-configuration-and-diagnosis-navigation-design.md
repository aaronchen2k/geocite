# 配置与诊断室导航设计

## 目标

重组工作台左侧菜单，明确区分可维护的长期配置与诊断产生的结果；为竞品品牌、品牌事实库、阵地地图和问题总结建立首期信息架构与空状态规则。

## 全局工作上下文

顶部品牌选择器是唯一的品牌上下文入口。所有下列页面均展示和操作当前选中品牌的数据：基础配置、品牌问题、竞品品牌、品牌事实库、发起诊断、诊断报告、问题总结、竞品对比、样本库与阵地地图。

页面内不再增加品牌切换器。切换顶部品牌时，当前页面刷新为该品牌的数据；若该品牌尚没有相应资产，展示对应的空状态。诊断结果页可提供“诊断批次”选择器，但该选择器仅切换当前品牌的历史诊断批次。

## 左侧导航

保留现有紧凑的两层侧栏结构，将配置类页面从其他父菜单独立为“配置”，将运行与分析结果归入“诊断室”。

```text
工作台

配置
  基础配置
  品牌问题
  竞品品牌
  品牌事实库

诊断室
  发起诊断
  诊断报告
  问题总结
  竞品对比
  样本库
  阵地地图
```

“品牌事实库”属于配置，因为它是一项可长期维护、可人工校正的品牌资产。“阵地地图”属于诊断室，因为它是根据诊断产物计算出的分析视图，而非人工配置。

## 竞品品牌

竞品品牌页维护当前品牌参与诊断和对比的竞品集合。首期表格以“名称”为主识别信息，并支持以下属性：

- 别名：将“腾讯文档 / 腾讯 Docs / Tencent Docs”等名称映射为同一竞品，用于提高样本识别准确性。首期可为空。
- 市场：限定竞品参与比较的统计范围，例如中国市场或海外市场。当前仅单一市场时可为空。
- 启停：停用的竞品不进入新的诊断与统计分母，但保留其历史配置及历史报告中的结果，避免删除造成历史失真。

名称、别名、市场、状态为列表的首期可见字段；名称是必填项，其余字段可为空。状态变化应以未来运行批次为边界，不重算既有报告。

## 品牌事实库

品牌事实库位于“配置”，用于沉淀诊断从样本、报告和证据中提取的候选事实，并允许人工维护。

### 生命周期

1. 首次诊断完成后，系统从诊断证据中提取候选事实。
2. 用户可确认、修改、合并、驳回或标记事实为过期。
3. 已确认或人工新增的事实进入品牌事实库，供后续诊断、问题总结和阵地地图使用。
4. 人工修订以校正版本保留，不覆盖原始诊断证据。

每条事实的后续列表至少应支持：事实内容、来源、置信度、状态、最后更新；具体模型与编辑流程不在本次首期页面实现范围内。

### 首期空状态

当当前品牌尚无事实时，页面说明“完成首次诊断后自动生成”，并保留“新增事实”入口。该入口允许品牌运营人员提前补充基础事实，不要求先运行诊断。

## 阵地地图

阵地地图位于“诊断室”，由当前品牌的事实库、品牌问题、有效问题样本、竞品配置和诊断表现共同生成。它用于展示品牌与竞品在主题或需求场景中的占位和可争取空间。

首期不手工编辑地图。若当前品牌没有可用诊断批次，显示“等待首份诊断结果”，解释生成前提并提供“发起诊断”入口。诊断完成后才呈现地图内容和相应的证据链接。

## 问题总结

在“诊断室”中新增与“诊断报告”并列的“问题总结”菜单。它承担与 GeoLook “差距诊断”相近的职责，但用品牌团队已有的“问题”语言组织内容，避免成为另一份全局报告。

### 内容范围

以一个品牌问题为一个条目，按优先级列出待处理问题。每个条目包含：

- 问题原文；
- 差距发现，例如当前品牌在提及、引用或覆盖场景上相对竞品的不足；
- 判断依据，连接到问题样本、竞品对比和关联回答证据；
- 优先级及其可解释原因；
- 跳转“查看证据”或“前往样本库”的操作。

问题总结不重复诊断报告的全局指标，不制造没有证据支撑的行动结论，也不在页面内承担品牌切换。证据不足时明确展示“暂无结论”，而不是推测差距。

## 交互与视觉规则

- 沿用既有克制、专业、紧凑的后台样式：系统字体、低饱和中性色、细边框与短时状态反馈。
- 侧栏仅有当前页高亮；父级展开状态清晰且可用键盘操作。
- 空状态说明“为何为空、满足什么条件会生成、下一步可做什么”，不展示虚构图表或假数据。
- 主要操作保持现有按钮语言：事实库使用“新增事实”，阵地地图使用“发起诊断”，问题总结使用“查看证据”。
- 诊断批次切换为局部上下文控件；切换时加载对应批次数据并保留可理解的空状态或加载状态。

## 验收标准

- 用户可在侧栏明确分辨“配置”的可维护资产与“诊断室”的运行及结果页面。
- 当前顶部品牌决定全部页面的数据边界，页面中没有第二个品牌选择入口。
- 竞品名称、别名、市场、启停含义明确，停用不会改写历史报告。
- 未诊断品牌的品牌事实库与阵地地图分别呈现不同且可行动的空状态。
- 问题总结可追溯到具体问题和证据，且与诊断报告、竞品对比、样本库的职责不重叠。
