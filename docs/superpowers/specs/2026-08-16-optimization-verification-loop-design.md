# 优化与验证闭环设计

## 1. 目标与范围

本设计将现有“诊断室 → 优化 → 验证”串成可追溯的工作闭环：诊断产生发现，发现进入优化工单，完成优化后重新诊断，系统比较前后变化；只有在优化动作和证据被明确关联时，才允许人工确认归因。

本轮范围包括：优化工单、破局矩阵、信源建设、网站优化、内容生产、可见趋势、问题追踪、效果归因、周期复测和对比测试。

本轮不包含：公司资产知识库、行业本体分析、文章自动生成或发布、自动绕过外部平台访问限制、绝对效果承诺。

## 2. 现状与设计原则

当前系统已按品牌保存诊断批次、原始样本、问题分类、模型表现和竞品表现；优化与验证页面尚为说明页，尚未连接业务数据。

设计遵循以下原则：

- 所有优化和验证均属于顶部已选择的当前品牌。
- 已完成诊断批次及其原始样本不可被后续配置覆盖。
- 趋势和前后变化可以自动计算；因果归因必须有优化动作和人工依据，不能由数值变化自动下结论。
- 对比测试与自动周期复测属于显式配置能力，不能被一次普通重跑隐式创建。
- 内容生产首期只管理计划和审核依据，不自动生成或发布文章。

## 3. 推荐方案：诊断批次驱动 + 优化动作显式关联

### 3.1 核心对象

| 对象 | 作用 | 关键字段 |
| --- | --- | --- |
| 诊断批次 | 不可变的测量快照 | 品牌、问题集版本、市场、参与引擎、采样方式、完成时间、指标快照 |
| 诊断发现 | 可行动的问题入口 | 来源批次、类型、范围、优先级、证据、推荐动作 |
| 优化工单 | 将发现转为执行动作 | 关联发现、动作类型、负责人、状态、截止时间、验收条件、完成说明 |
| 优化动作 | 工单完成时的可归因事实 | 动作时间、影响范围、变更说明、关联 URL/事实/信源、证据 |
| 验证比较 | 两个诊断批次之间的计算结果 | 基线批次、复测批次、可比性、指标变化、问题/引擎维度变化 |
| 归因记录 | 人工对“可能关联”的确认或否决 | 关联工单、比较、结论、依据、确认人、时间 |
| 对比实验 | 主动设计的对照验证 | 对照组、实验组、范围、成功指标、状态、运行引用 |
| 复测计划 | 定期创建诊断任务的配置 | 基线、频率、范围、通知、启停、最近执行状态 |

### 3.2 关系与数据流

```text
已完成诊断批次
  └─ 诊断发现 ──→ 优化工单 ──→ 已完成优化动作
                                      │
重新执行诊断 ──→ 复测批次 ──→ 验证比较 ──→ 可能关联
                                                       │
                                               人工归因记录
```

1. 诊断报告、问答汇总、竞品对比、样本库和站点体检中的发现可创建优化工单，并自动带入来源批次、问题、样本或 URL。
2. 工单从“待处理 → 进行中 → 待验证 → 已验证 / 未生效 / 已取消”流转。完成动作后进入“待验证”，同时记录完成时间与作用范围。
3. 用户重新执行诊断时，系统选择最近可比的已完成批次或工单前基线作为比较对象。比较只计算相同品牌、市场、问题集和采样口径下的变化；不满足条件时明确展示不可比较原因。
4. 系统把工单完成时间位于基线与复测之间的动作标为“可能关联”，但不自动写入因果结论。
5. 用户在效果归因页查看样本、问题表现、工单和变更证据后，确认“已确认归因”“无法确认”或“无明显影响”。

## 4. 页面职责与交互

### 4.1 优化

| 页面 | 输入 | 输出 / 操作 |
| --- | --- | --- |
| 优化工单 | 诊断发现、人工新增事项 | 创建、分派、更新状态、记录完成动作和验收条件；跳转至验证比较 |
| 破局矩阵 | 问题提及率、竞品占优、内容/事实覆盖 | 按影响与可实施性排序，创建一组工单 |
| 信源建设 | 未覆盖事实、未治理引用 URL、信源缺口 | 登记或关联信源资产，创建建设任务；不发布内容 |
| 网站优化 | 站点可达性、结构化数据、页面内容体检 | 创建技术修复工单并记录修复证据 |
| 内容生产 | 已审核事实、品牌问题缺口、竞品主题优势 | 建立选题与审核计划，关联事实与目标问题；不生成或发布文章 |

工单详情必须显示“从哪里来、要解决什么、完成了什么、下一次如何验证”。工单关闭前若没有验收条件，系统提示补充；工单可因暂不验证而取消，但必须填写原因。

### 4.2 验证

| 页面 | 自动数据 | 必须单独操作 |
| --- | --- | --- |
| 可见趋势 | 历次完成诊断的品牌可见率和指标快照 | 选择时间范围、问题/引擎筛选 |
| 问题追踪 | 同一问题在历次诊断中的提及、竞品和模型表现 | 选择重点问题、引擎和市场 |
| 效果归因 | 可比批次之间的变化、时间窗内完成的工单 | 查看证据并填写归因结论与依据 |
| 周期复测 | 手动重跑形成的批次及与基线的比较 | 配置频率、范围、通知和启停；选择基线 |
| 对比测试 | 对照组和实验组各自运行后的批次 | 创建实验、定义范围与成功指标、关联两组运行 |

可见趋势与问题追踪不创建新的诊断，它们消费已完成批次。效果归因和对比测试不能把单次重跑解释为因果或实验。周期复测的自动任务仅负责按计划创建诊断；结果比较仍使用同一可比性规则。

## 5. 状态与判定规则

### 5.1 工单状态

| 状态 | 可进入状态 | 规则 |
| --- | --- | --- |
| 待处理 | 进行中、已取消 | 必须有来源发现或人工创建原因 |
| 进行中 | 待验证、已取消 | 可持续补充执行记录 |
| 待验证 | 已验证、未生效、进行中、已取消 | 必须关联完成动作；复测完成后才能选择已验证或未生效 |
| 已验证 | 进行中 | 必须关联至少一条可比验证比较和验收说明 |
| 未生效 | 进行中、已取消 | 必须说明未达标原因或下一步动作 |
| 已取消 | 进行中 | 必须保留取消原因 |

### 5.2 比较可比性

比较至少检查品牌、市场、问题集版本、引擎集合、采样方式和规则版本。系统将结果分为：

- 可比：全部必需维度一致，可以计算整体和问题级变化。
- 部分可比：部分问题或引擎重叠，只计算重叠范围，并显示排除范围。
- 不可比：品牌、市场或采样方式不同，不给出整体变化结论。

### 5.3 归因结论

归因记录只能使用以下结论：`已确认归因`、`可能关联`、`无法确认`、`无明显影响`。其中：

- `可能关联` 可由系统根据工单完成时间和可比比较自动产生。
- 其余结论必须由人工填写依据后产生。
- 任一结论均展示样本量、比较条件和数据缺口；不使用“保证有效”“必然提升”等表述。

## 6. 异常与边界

- 无两次完成诊断时，可见趋势显示空状态和“至少需要两次完成运行”。
- 没有可比基线时，复测仍可完成，但比较显示“未建立可比基线”。
- 复测运行失败或部分失败时，保留已有样本和失败原因，不生成完整效果结论。
- 工单在复测前被修改时，比较仍引用已记录的完成动作版本，避免事后修改影响历史归因。
- 一个工单可关联多个复测；最终归因以最新有效归因记录为当前结论，历史记录可追溯。
- 对比实验的对照组、实验组或成功指标变更后，原实验应结束并创建新版本，避免混合口径。

## 7. 实施切分与验收

### 第一阶段：可见变化与工单闭环

1. 新增诊断发现与优化工单，支持从报告、问答、竞品和站点体检创建工单。
2. 记录工单完成动作和验收条件。
3. 基于已完成诊断批次实现可见趋势、问题追踪和前后比较；先支持手动重跑。
4. 验收：可从一个发现创建工单，完成工单后重跑诊断，看到可比性判断与前后变化。

### 第二阶段：归因与周期复测

1. 实现归因记录、人工确认和证据链接。
2. 实现复测计划、启停、执行状态和通知。
3. 验收：工单前后变化只能显示为可能关联，人工确认后才显示已确认归因；定时复测可生成新的批次。

### 第三阶段：对比测试

1. 实现实验定义、对照/实验范围与成功指标。
2. 关联两组批次并按成功指标生成实验结论。
3. 验收：未定义对照组、实验组和成功指标时不能生成实验结论；变更任一条件后创建新实验版本。

## 8. 测试策略

- 服务端：状态流转、品牌隔离、不可变批次快照、比较可比性、归因权限和计划调度。
- 前端：从诊断发现创建工单、待验证工单跳转到比较、不可比提示、归因依据必填、自动复测启停。
- 端到端：完成一次基线诊断 → 创建并完成工单 → 完成复测 → 查看变化 → 人工确认归因。
- 回归：既有诊断报告、问答汇总、竞品对比、样本库和当前品牌切换行为保持可用。
