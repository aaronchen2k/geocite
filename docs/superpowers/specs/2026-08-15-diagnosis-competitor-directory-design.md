# 诊断配置竞品名录设计

## 目标

在诊断配置页提供“竞品名录”字段，运营人员以英文逗号或中文逗号分隔输入竞品品牌名称。配置保存后，生成诊断问题的默认提示词包含该竞品上下文，帮助模型生成品牌比较相关的问题。

## 范围

- 每个品牌保存一份竞品品牌名称列表。
- 配置页加载、编辑并保存该列表。
- 问题生成的默认提示词显示该列表。
- 本次不建立独立竞品实体，不采集竞品网站或其他资料，也不改动已有诊断执行流程。

## 数据与接口

`brands` 表增加可空的 `competitors` simple-json 列，类型为 `string[] | null`。

诊断配置的读取和保存接口新增 `competitors: string[]`：

- `GET /brands/:brandId/diagnosis-questions` 始终返回数组；未配置时返回空数组。
- `PUT /brands/:brandId/diagnosis-questions` 接受可选的 `competitors: string[]`，以便前端将逗号分隔输入解析后提交。
- 未传该字段时保持既有兼容语义，不覆盖已有竞品配置。

服务端以单一标准化函数处理竞品名称：按中英文逗号拆分，移除首尾空白和空项，按首次出现顺序去重。每个名称限制为 200 个字符，总数最多 50 个；不合规输入返回验证错误。标准化后为空时持久化为 `null`，接口响应为 `[]`。

## 前端交互

在现有“最多抓取 URL 数”配置卡中新增“竞品名录”单行文本字段，字段说明为“多个竞品品牌名称请用逗号分隔”。

加载配置时，数组用 `，` 连接显示；保存时，前端将输入拆分为数组后与问题、提示词和 sitemap 限制一并提交。保存成功后，使用服务端返回的标准化数组回填，以直观反映去重和空白清理结果。

## 提示词生成

`buildBrandQuestionPrompt` 的输入扩展为可选竞品数组，并在模板变量中增加 `{{competitors}}`。

提示词模板新增“竞品名录”段：配置了竞品时以每行一个品牌名称输出；未配置时输出“未填写”。自定义提示词及其重置继续沿用现有行为：重置时根据当前品牌与竞品信息重新生成默认提示词；生成请求同样将竞品上下文纳入默认基础提示词。

## 错误处理与兼容性

- 保留现有问题、提示词和 sitemap URL 数的验证与保存行为。
- 空输入合法，代表清空竞品名录。
- 历史品牌数据因列可空而无需迁移回填；读取时自然回退为空数组。
- 无法满足长度或数量限制的请求由 DTO/服务层拒绝，前端显示既有 API 错误提示。

## 测试

- 单元测试覆盖竞品输入标准化：中英文逗号、空项、首尾空白、重复项、清空行为与限制。
- 诊断配置服务测试覆盖读写和空值回退。
- 提示词测试覆盖有竞品与无竞品两种渲染结果。
- 前端测试（如现有测试基础设施适用）覆盖字段显示、提交内容和服务端规范化结果回填。
