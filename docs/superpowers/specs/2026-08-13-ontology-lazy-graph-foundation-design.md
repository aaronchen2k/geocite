# 跨行业本体与 Lazy Graph 基座设计

## 目标

建立可配置、可复用于多个行业的知识建模基座。首期让用户在某个 Brand 工作区内，手工创建、编辑、保存并发布 Lazy Graph；二期基于已发布图谱版本生成可审阅、可追溯的行业专业文档。

`乐堡论文` 仅是当前 Brand 示例，不得作为本体、图谱或界面文案中的固定业务值。当前一期范围覆盖所选 Brand 的全部站点与其已配置的诊断引擎。

## 范围与分期

### 一期：工作区与图谱建模

- 统一 Brand 上下文，切换 Brand 后刷新当前页面的全部 Brand 相关数据。
- 修正执行诊断页：名称、范围、运行记录、运行状态及新建运行均绑定当前 Brand。
- 提供 Lazy Graph 的多图谱管理、手工节点/关系编辑、保存、草稿和发布版本。
- 提供通用本体核心与可配置行业包，支持逐步引入不同行业的术语和约束。
- 图谱节点和关系可引用 Brand、站点、Engine、执行诊断运行和证据等已有数据。

### 二期：专业文档

- 由用户选择一份已发布的图谱版本和行业文档模板生成初稿。
- 文档中的事实、结论和引用均能回溯到图谱元素、证据或诊断快照。
- 文档编辑不反向悄悄修改已发布图谱；需要改变知识时，创建新的图谱草稿和版本。

### 明确不包含

- 首期不从站点资料、诊断结果或上传文件自动抽取、推断或生成图谱。
- 首期不调用 AI 自动建图；数据可被接入并在画布中手工引用。
- 首期不把任一行业的节点、关系或文档结构硬编码为平台全局规则。

## 关键设计

### 1. Brand 工作区上下文

Header 中的 Brand 下拉框是唯一的当前 Brand 来源。它持有共享 `currentBrand` 状态（至少包括 `id`、`name`、`code`、`website`、`industry`、`engineIds`），并负责品牌切换事务：

1. 用户选择 Brand 后调用默认 Brand 接口；服务端确认成功才提交本地状态。
2. Header 更新共享状态，并发布 Brand 变更信号。
3. 当前展示的业务页订阅该状态，取消或忽略旧请求、清空旧 Brand 视图数据，并用新 `brandId` 重取数据。
4. 共享缓存必须按 `brandId` 分区；无法分区的缓存须在切换时失效。
5. 请求尚未完成时显示加载态或空态，不能显示旧 Brand 内容，也不能用“乐堡论文”作为展示回退。

执行诊断页不得仅在挂载时读取默认 Brand。它应响应 Brand 上下文变化，重新获取该品牌的运行历史和状态；启动运行时使用上下文中的 `brandId`。切换发生在运行中时，旧运行的 SSE/轮询连接必须关闭，旧响应不得覆盖新品牌的数据。

### 2. 通用本体核心

核心模型不定义行业专有概念，只提供以下稳定语义：

| 对象 | 职责 | 必要属性 |
| --- | --- | --- |
| `OntologyPackage` | 可安装/启用的行业语义包 | 标识、名称、版本、适用行业、状态 |
| `ConceptType` | 可创建节点的类型定义 | 包标识、代码、名称、属性定义、是否允许实例化 |
| `RelationType` | 可创建边的类型定义与约束 | 包标识、代码、名称、源/目标类型约束、基数、方向性 |
| `Graph` | 一个 Brand 下的具名知识图谱 | Brand、名称、描述、启用行业包、当前草稿/发布版本 |
| `GraphVersion` | 图谱的不可变保存快照 | 图谱、版本号、状态、创建者、保存时间、变更说明 |
| `Node` | 某版本内的概念实例 | 类型、名称、属性、位置/展示元数据、外部引用 |
| `Edge` | 某版本内的关系实例 | 关系类型、源节点、目标节点、属性、证据引用 |
| `EvidenceReference` | 支撑某项陈述的数据定位 | 来源类型、来源 ID/URL、摘要、采集时间、可信度 |

`OntologyPackage` 通过配置提供行业词汇、可用关系、字段约束、默认画布样式和二期文档模板，不改变核心表结构。新行业以新增包的方式接入；同一 Brand 的不同图谱可选择不同或多个兼容包。

### 3. Lazy Graph 的保存与编辑

每个 Brand 可保存多张具名图谱，例如“全景本体”“竞品关系”“内容主题”。一张图谱只有一个可编辑草稿，可有多个不可变的已发布版本。

- 新建图谱时必须归属当前 Brand，并记录所用行业包和版本。
- 手工添加/修改/删除节点、关系及画布布局只作用于草稿。
- 保存草稿记录修改时间和操作者；发布创建不可变 `GraphVersion`。
- 发布版本可查看、作为二期文档输入或复制为新草稿；不得原地修改。
- 节点和关系可选择性关联平台已有对象。引用关系不复制原始诊断数据，展示时通过来源 ID 取详情；版本发布时保存必要摘要，避免来源变化破坏审计。
- 没有图谱的 Brand 进入 Lazy Graph 时显示空状态和“新建图谱”入口，不从其他 Brand 借用数据。

“Lazy”表示画布按需载入：先读取图谱元数据和当前可见区域/局部子图，节点详情、证据和相邻关系在用户展开或查看时再加载。保存、版本和引用语义不因此变为延迟或不一致。

## 主要数据流

```text
Header Brand 选择
  -> 更新 currentBrand(brandId)
  -> 失效/分区 Brand 缓存
  -> 当前页面重新取数
      -> 执行诊断：历史、状态、范围、运行
      -> Lazy Graph：图谱列表、草稿或空状态

手工编辑 Lazy Graph 草稿
  -> 保存草稿
  -> 发布不可变 GraphVersion
  -> 二期：选定版本 + 行业模板 -> 专业文档初稿
```

## 接口与状态约定

- 所有 Brand 作用域 API 的路径或查询参数必须明确携带 `brandId`；服务端验证资源归属，避免跨 Brand 读取和写入。
- 前端请求带随 Brand 切换递增的上下文版本/取消信号；响应只有在其 `brandId` 与当前上下文匹配时才可写入状态。
- 页面本地状态分为与 Brand 无关的展示状态（如展开面板）和 Brand 相关的数据状态。前者可保留，后者必须在切换时重置。
- 当前 Brand 不存在、被禁用、无站点、无 Engine、无图谱或加载失败时，给出明确空态/错误态和恢复动作。

## 错误处理与审计

- Brand 切换接口失败时保持原 Brand 上下文，并显示失败反馈；不得先切换页面数据再回滚。
- 图谱保存冲突时提示用户基于最新草稿合并或复制，不静默覆盖他人修改。
- 删除 Brand 前检查其图谱和已发布版本；采用软删除或显式归档策略，不破坏文档的证据链。
- `GraphVersion`、节点/关系来源和行业包版本必须可查询，以支持二期文档的事实追溯。

## 验收标准

1. 在执行诊断页切换 Header 中的 Brand 后，无需刷新浏览器或重新进入路由，页面名称、范围、运行历史和状态均更新为新 Brand 数据。
2. 快速连续切换品牌时，任何旧 Brand 的请求、SSE 或轮询结果均不能出现在新 Brand 页面。
3. 不存在 Brand 或接口不可用时，执行诊断不显示“乐堡论文”这类固定品牌名。
4. 每个 Brand 能创建多张独立的具名图谱；跨 Brand 不能读取或编辑图谱。
5. 用户可手工编辑草稿、保存、发布版本，并在发布后恢复查看该版本的节点、关系、布局、行业包版本和证据摘要。
6. 首期不会自动从资料或诊断结果生成节点或关系。
7. 二期文档只能选择已发布图谱版本，并能追溯每条引用的图谱和证据来源。

## 测试策略

- 前端组件测试：Header 切换 Brand 后，当前页面接收新上下文、显示加载态并只渲染新响应；验证“乐堡论文”不作为回退。
- 前端集成/端到端测试：在执行诊断页切换两个 Brand，断言请求 URL、名称、运行列表和范围均变更；运行中切换时旧连接被关闭。
- 服务端测试：Brand 作用域 API 拒绝不归属资源；图谱、草稿、版本和证据引用遵守 Brand 归属与不可变规则。
- 行为测试：手工创建多张图谱、发布版本、切换 Brand、回到原 Brand 后确认图谱和版本完整且隔离。

## 实施顺序

1. 引入共享 Brand Workspace 状态，替换 AppShell 和业务页各自读取默认 Brand 的模式；为执行诊断补齐刷新与竞态保护测试。
2. 建立图谱核心实体、Brand 归属、行业包配置、草稿/发布版本 API 与迁移。
3. 实现 Lazy Graph 图谱列表、空态、手工节点/关系编辑、按需加载和版本发布界面。
4. 接入站点、Engine、诊断运行和证据的只读引用选择器。
5. 基于已发布版本和行业包模板实现二期专业文档。

## 设计自检

- 已明确首期仅手工建图，未把 AI 自动抽取混入范围。
- Brand 是所有业务数据的硬隔离边界，Header 是唯一上下文来源。
- 通用核心与行业语义包分离，避免将 GEO 或“乐堡论文”硬编码为全局本体。
- 草稿可变、发布版本不可变，满足后续专业文档的可追溯要求。
