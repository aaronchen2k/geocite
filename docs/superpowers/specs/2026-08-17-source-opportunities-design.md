# 信源机会设计

## 目标

基于诊断中大模型回答实际引用的公开 URL，发现可验证的内容缺口，并把建议转为人工审核的内容计划/优化工单。系统不自动生成、发布或分发文章，不把高引用误称为权威。

## 证据基础

每条 API 或成功网页复核样本保留：运行、品牌、引擎、问题、两层问题分类、回答文本、解析出的引用域名、当前品牌提及、竞品提及和原始回答链接。信源机会只从同一品牌、同一诊断批次的可追溯样本生成。

## 页面结构

### 问答汇总：证据层

每个问题增加“查看引用信源（N）”折叠区：

- 以域名汇总引用次数、引用引擎数、来源归属（自有官网、竞品官网、第三方）和来源类型（首期可为未分类）。
- 展开域名显示回答片段、引擎、品牌/竞品提及结果和原 URL。
- 没有可解析公开 URL 时显示“该问题的回答未识别到公开引用链接”。

### 优化 → 信源机会：分析层

按机会类型分组，并按“引用次数、覆盖问题数、差距程度”排序。每张机会卡可回链问答汇总、原问题、样本和 URL 证据。

## 三类固定机会

### 1. 高引用信源里，缺少你的品牌

判定：第三方信源在同一主题的样本中达到高引用阈值，且关联回答中当前品牌提及率为 0 或低于配置阈值。

建议：创建“品牌事实覆盖”内容计划，包含原问题、信源、回答证据、建议事实范围和验收条件。

### 2. 高引用信源里，竞品领先你的品牌

判定：高引用信源关联样本中至少一个启用竞品提及率高于当前品牌，且竞品提及率大于 0。

建议：创建“竞品差距”内容计划，包含领先竞品、双方提及率、问题分类与证据。计划不得包含恶意抹黑或不可核验的竞品说法。

### 3. 高引用信源里，你的官网没有对应的页面内容

判定：高引用信源对应的问题主题，在本次网站抓取页面中找不到匹配的标题、正文主题或可引用事实段落。

建议：创建“官网内容缺口”计划，带入建议页面类型、关联问题、参考信源、待补真实事实和验收条件。

## 规则与边界

- “高引用”首期仅表示在本次诊断回答中被引用次数较高，默认阈值为至少 3 次且覆盖至少 2 个问题；页面应同时显示真实次数，后续再提供人工可信度评级。
- 同一 `运行 + 问题主题 + 域名 + 机会类型` 去重；同一域名可出现在不同机会类型中。
- 域名归属通过当前品牌官网域名、启用竞品官网/名称映射和其余第三方规则判断；无法判定时标为第三方/待确认。
- 创建动作只创建现有优化工单/内容生产计划，预填来源证据、建议内容形态、关联问题和验收条件；不产生文章正文，不触发外部发布。
- 后续企业事实库接入后，内容计划必须关联至少一条经审核的真实事实才可进入生产阶段；首期显示“待补事实依据”。

## 验收标准

- 问答汇总能按问题查看实际引用域名及回答证据。
- 三类机会只使用当前品牌、当前运行的样本，且每张卡可追溯。
- 竞品领先机会不把 0% 竞品显示为领先者。
- 官网缺口机会能展示本次抓取中为 0 的匹配页面证据。
- 创建内容计划不会生成或发布文章，并能回填原问题、信源与验收条件。
