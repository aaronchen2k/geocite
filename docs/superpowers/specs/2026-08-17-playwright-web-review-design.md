# Playwright 网页复核设计

## 目标与边界

在执行诊断的 API AI 回答采样后，增加网页端真实用户环境复核。复核覆盖本次诊断已选中的全部引擎，但只对抽中的“引擎 × 问题”样本执行。它用于校正 API 粗扫指标、保留可追溯网页证据，不生成内容、不发布内容、不规避验证码或平台风控。

首期运行于客户电脑上的 Electron 应用：本地后端控制客户已安装的 Chrome，每个引擎使用独立持久化 Profile；客户自行完成官方网页登录、扫码和 MFA。应用不得接收、记录或保存账号密码、验证码。

## 基础配置：诊断采样范围

在基础配置的“抓取范围”章节增加：

- API 目标问句数，默认 10，范围 4–150；后续可提供免费/标准/专业的预设值，但首期只保存实际数量。
- 问题分类比例，包含“品牌基础提问”“核心业务能力提问”“竞品对比提问”，默认 `1:2:1`，三个值均须大于 0。
- 总数不能被比例整除时，余数按“核心业务能力、品牌基础、竞品对比”的顺序补齐。

AI 补充问题提示词按冻结的实际分类数量生成问题。服务端必须校验总数、分类、比例和问题文本；不合格候选题不能保存。

## 执行步骤

原七步流程调整为八步：

1. 读取上次基线。
2. 抓取网站内容。
3. 站点 AI 可触达性检测。
4. 页面与内容体检。
5. AI 回答采样：仅 API 粗扫。
6. Playwright 网页复核：复核已选样本。
7. 规则验收与前后对比：优先使用成功网页复核样本校正指标。
8. 生成诊断结果。

创建运行时冻结问题、分类数量、引擎、抽样规则版本、随机种子和最终复核选样清单。历史批次不可受之后配置变化影响。

## 选样规则

选样单位为“引擎 × 问题”的 API 样本。

1. 全部核心业务能力问题强制复核。
2. API 回答命中当前品牌的全部问题强制复核。
3. 其余未命中且非核心样本随机抽取 25%。
4. 若仍未达到 API 样本总数的 30%，从剩余样本补抽到 30%。

30% 是最低抽样目标；强制规则优先，因此实际比例通常高于 50%。同一样本可有多个入选原因，但仅执行一次网页复核。API 失败、会话失效、验证码、风控、页面异常均记录为“未复核/排除”，不得归为品牌未提及。

## Electron 本地 Chrome

每个引擎拥有独立的 Chrome 持久化目录：

```text
{应用数据目录}/playwright-profiles/{engineCode}/
```

Playwright 使用客户本机已安装的 Chrome 与该目录启动持久化上下文。Cookie、localStorage 等由 Chrome 正常保存；首期不导出 `storageState`，不下载 Playwright 自带 Chromium。

安装依赖：

```bash
pnpm --dir server add playwright-core
```

运行时探测 Windows/macOS 默认 Chrome 路径；找不到时允许用户选择 Chrome 可执行文件。使用：

```ts
chromium.launchPersistentContext(profilePath, {
  executablePath: detectedChromePath,
  headless: false,
});
```

## 引擎管理

引擎管理表格增加“网页复核可用状态”列，只展示：

- 不可用：Chrome 未发现、检查异常、验证码/风控、受控浏览器冲突等；展示最近原因。
- 待登录：Chrome 可用但该引擎 Profile 无有效登录态。
- 已就绪：已通过登录态与问答页健康检查，可参与网页复核。

表格操作为：

- 刷新：短暂用该 Profile 执行健康检查，更新状态，不清理登录态。
- 重置：关闭本应用此前为该引擎启动的受控 Chrome；重新启动可见 Chrome。若未登录，则保留在官方登录页等待客户输入；检测到登录成功后更新为已就绪。重置不删除 Cookie。

“清除网页登录数据”仅作为二级危险操作，并要求二次确认。

## 受控浏览器实例标识

数据库持久化两个层级的标识：

- `profileId`：某个引擎的长期 Profile 身份。
- `launchId`：每次启动受控 Chrome 时新生成的 UUID。

启动参数包含：

```text
--geocite-review-launch-id={launchId}
--user-data-dir={profilePath}
```

持久化 `engineId`、`profileId`、`currentLaunchId`、`currentProcessId`、`launchStatus`、`startedAt`、`lastHeartbeatAt`、`lastCheckedAt`、`lastFailureReason`、`lastReadyAt`。重置时按命令行的 `launchId` 查找进程，并同时验证 Chrome 可执行文件与专属 `profilePath`；禁止仅按 PID 结束进程，以避免 PID 复用误杀其他 Chrome。

运行内存还维护 `engineId -> BrowserContext / PID` 映射，便于 Playwright 正常关闭窗口；数据库用于应用重启后的遗留进程识别和审计。

## 证据、口径与失败处理

网页复核记录独立于 API 样本，关联运行、API 样本、引擎、问题和入选原因，并保存网页回答文本、提及判断、必要截图/元数据、时间、状态和排除原因。不得回写 API 原始样本。

复核按单引擎串行、低频执行。出现登录失效、验证码或风控时立即停止该引擎后续网页复核，运行仍可部分完成。

报告展示 API 总量、最低目标、强制复核、随机抽取、实际成功复核和排除原因，并固定附注：

> 本次共采集 XX 条目标问句，全部通过官方 API 批量预扫描；其中 XX 条关键样本经过网页端真实用户环境复核，最终指标以复核样本校正得出；其余 API 扫描结果仅供参考。

## 验证标准

- 比例配置、分类生成和非整除配额有服务端测试。
- 复核选样覆盖强制、随机、补足、重复原因合并和冻结复现。
- 三种网页登录状态及刷新、重置、遗留进程关闭有 Electron/本地后端测试。
- Chrome 不存在、登录失效、验证码/风控、窗口异常均得到明确状态和报告排除原因。
- 复核结果不覆盖 API 样本，报告能同时展示两类证据及校正口径。
