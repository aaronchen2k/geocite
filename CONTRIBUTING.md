Thank you for your interest in contributing to GeoCite! We welcome bug reports, feature suggestions, documentation improvements, and code contributions.

参与本项目即表示您同意遵守 [Apache License 2.0](./LICENSE.md) 及本贡献者协议条款。

## Before You Contribute / 贡献前须知

### 1. Read the License / 阅读许可证

GeoCite uses the **Apache License 2.0**. Please read [LICENSE.md](./LICENSE.md) carefully before contributing. Key points:

GeoCite 采用 **Apache License 2.0** 开源许可证。贡献前请仔细阅读 [LICENSE.md](./LICENSE.md)，核心要点如下：

- You may use, modify, and distribute the software for commercial and non-commercial purposes
- 您可以出于商业和非商业目的使用、修改和分发本软件
- The license includes attribution, notice, and patent provisions
- 许可证包含署名、声明与专利相关条款

### 2. Sign the CLA / 签署贡献者许可协议

**All contributors must sign our Contributor License Agreement (CLA) before their pull request can be merged.**

**所有贡献者在合并 Pull Request 前必须签署贡献者许可协议（CLA）。**

We use [CLA Assistant](https://cla-assistant.io) to automate this process. When you open your first Pull Request, CLA Assistant will automatically post a comment with a link to sign the CLA electronically. No paper forms required.

我们使用 [CLA Assistant](https://cla-assistant.io) 自动化该流程。当您提交首个 Pull Request 时，CLA Assistant 会自动发表评论并提供电子签署链接，无需纸质表格。

> 🔒 Your CLA signature ensures that both you and the GeoCite project are legally protected, and enables us to offer commercial licenses while keeping the codebase freely available to the community.
>
> 🔒 签署 CLA 既保障您与 GeoCite 项目的合法权益，也使我们能够在保持代码库向社区免费开放的同时提供商业许可。

## How to Contribute / 如何贡献

### Reporting Bugs / 报告缺陷

1. Search existing issues to avoid duplicates / 搜索现有 Issue 避免重复
2. Use the Bug Report template / 使用缺陷报告模板
3. Include: steps to reproduce, expected behavior, actual behavior, environment details / 请包含：复现步骤、预期行为、实际行为、环境信息

### Suggesting Features / 功能建议

1. Open a Discussion or Feature Request issue / 发起讨论或功能请求 Issue
2. Describe the use case and expected outcome / 描述使用场景与预期效果
3. Be open to feedback and iteration / 保持开放态度，接受反馈与迭代

### Submitting Code / 提交代码

1. Fork the repository and create a branch from `main` / Fork 仓库并从 `main` 分支创建新分支
2. Write clear commit messages following [Conventional Commits](https://www.conventionalcommits.org/) / 遵循 [Conventional Commits](https://www.conventionalcommits.org/) 规范编写清晰的提交信息
3. Add/update tests as appropriate / 按需添加或更新测试
4. Ensure all CI checks pass / 确保所有 CI 检查通过
5. Open a Pull Request with a clear description / 提交 Pull Request 并附清晰描述
6. Sign the CLA when prompted / 按提示签署 CLA
7. Respond to review comments promptly / 及时响应评审意见

## Code Standards / 代码规范

- Follow the existing code style and conventions / 遵循现有代码风格与规范
- Write meaningful comments for complex logic / 为复杂逻辑编写有意义的注释
- Keep PRs focused and reasonably scoped / 保持 PR 聚焦且范围合理
- Update documentation when changing public APIs / 修改公共 API 时同步更新文档
