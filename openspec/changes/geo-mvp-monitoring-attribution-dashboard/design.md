## Context

本变更是空仓库中的首个 GEO 产品切片，面向 GEO 工程师和营销负责人。MVP 必须形成“配置监测 → 留存回答证据 → 解释表现 → 汇报趋势”的闭环，并允许后续接入内容生成、知识库和发布能力。主流 AI 平台的接口形态和可访问性不一致，回答具有随机性，且监测结果需要可追溯。

## Goals / Non-Goals

**Goals:**

- 以统一的监测任务模型接入多个 AI 平台，并保留原始回答、查询参数、执行时间和解析结果。
- 将品牌表现拆成可解释的引用指标、推荐层级、语义准确性和负面事件。
- 通过可复算的归因规则输出语义匹配、信源权重、E-E-A-T、结构化数据和爬虫可访问性结果。
- 以项目/品牌为边界提供趋势看板、竞品对比、数字资产指数和周期报告。
- 让平台适配器、评分规则和报告模板可替换，支持后续扩展行业模板与商业化能力。

**Non-Goals:**

- MVP 不实现 AI 内容生成、知识库、内容发布、多租户、计费或开放 API。
- MVP 不承诺绕过平台登录、验证码、反爬或服务条款限制；无法合法采集的平台必须显示不可用状态。
- MVP 不把单次 AI 回答当作绝对事实；趋势和报告必须标记样本量、采集时间及不确定性。

## Decisions

1. **采用平台适配器 + 统一证据模型。** 每个平台实现独立的查询、限流和解析适配器，输出统一的 `MonitoringRun`、`AnswerEvidence`、`MentionFinding` 和 `SourceReference`。相比在业务层写平台分支，这样能隔离平台变更并支持新增平台；相比只保存聚合指标，统一证据模型能支持复核和重新计算。

2. **采用异步任务队列执行监测。** 用户保存配置后创建周期任务，调度器按平台和项目限流执行，失败任务重试并记录原因；前端读取任务状态和历史结果。同步请求实现简单但会被平台延迟、超时和限流拖垮。

3. **原始回答不可变、派生分析可重算。** 保存脱敏后的原文、查询、平台、模型/版本（若可得）、时间戳和证据哈希；引用判定、评分和指数作为带规则版本的派生数据。这样可审计评分变化，也允许规则升级而无需重新访问平台。

4. **MVP 使用可解释的规则与模型混合评分。** 语义匹配使用向量相似度并保存模型/阈值；引用层级、负面判定、E-E-A-T 和数字资产指数使用版本化规则与加权公式，并展示组成项。相比完全黑盒模型，更便于客户验证和调优；相比纯人工，能保持规模化和一致性。

5. **以项目为主数据隔离边界。** 项目包含品牌、关键词、竞品、监测平台和内容资产 URL；所有查询、结果、看板和报告都必须带项目标识。权限体系先保留单项目用户边界，为后续多租户迁移保留 owner/tenant 字段。

6. **报告基于指标快照而非实时重算。** 周报/月报引用周期内已完成的快照，包含样本量、异常和数据缺口；生成失败不影响看板数据。实时看板与报告分别优化可读性和可复盘性。

## Risks / Trade-offs

- [平台访问受限或规则变化] → 适配器返回明确的 `unavailable/rate_limited/parse_failed` 状态，保留失败原因和最后成功时间，不静默填充数据。
- [AI 回答随机导致趋势噪声] → 支持同关键词多次采样，展示样本量和置信提示，指数只使用完成且有效的样本。
- [负面判定误报] → 保存触发片段和判定依据，允许人工标记误报；预警默认去重并支持静默窗口。
- [抓取内容含个人信息或受版权保护文本] → 只采集完成分析所需的最小内容，脱敏、限制访问和保留周期，并在平台条款允许范围内运行。
- [评分体系被过度解读] → 看板同时展示原始证据、分项分数、规则版本和数据覆盖率，不只展示单一指数。
- [后续多租户改造成本] → 领域模型预留 tenant/owner 关联，MVP 仍不开放 OEM 和跨租户管理。

## Migration Plan

1. 创建项目、品牌、关键词、竞品、平台配置和监测结果的初始数据结构。
2. 先以一个可合法访问的平台适配器完成端到端链路，再逐个平台增加适配器和契约测试。
3. 上线时默认关闭外部平台调用，先导入/回放固定样本验证解析、评分和报告，再按项目开启真实采集。
4. 采用版本化迁移和特性开关发布；若外部平台异常，暂停对应适配器并继续展示历史数据，回滚只关闭新任务，不删除已保存证据。

- 首批正式支持的平台及每个平台允许的采集方式、频率和鉴权方式是什么？
- 语义准确性、E-E-A-T 和数字资产指数的初始阈值/权重由谁验收？
- 预警通知首期接入站内、邮件还是企业微信/钉钉？
- 原始回答的保留周期、脱敏规则和项目级访问角色需要满足哪些合规要求？
